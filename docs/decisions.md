# 决策记录

只记录会长期约束后续工作的决定，不记录实现细节。

## 0001 · 命名与仓库划分（2026-11-09）

| 对象 | 决定 | 说明 |
|---|---|---|
| npm 包名 | `dsh-bazaar` | 安装标识，发布后不再改 |
| 站点品牌 | 「DSH 插件市场」 | 与包名解耦，可随时调整，不影响安装命令 |
| 域名 | `dshbazaar.io` | 站点部署在域名根路径 |
| 仓库 | `dshbazaar/dshbazaar` | 单一仓库，不按域名命名 |

**为什么仓库不叫 `dshbazaar.io`**：GitHub 仓库名与域名无关，`.io` 结尾反而让 URL 读起来像网址；自定义域生效后，Pages 服务在域名根路径，默认子路径那层不会暴露给用户，改名没有收益。

**为什么现在不拆仓**：站点、索引生成、插件三者共用同一份数据格式与构建脚本，拆开会先引入跨仓同步成本。按职责拆分留到确有需要时再做。

### 未来若拆分

- `dshbazaar/plugin` —— DSH 插件包（`packages/dsh-bazaar` 独立出去）
- `dshbazaar/site` —— 站点与索引生成

理由：按职责命名比按域名命名更能表达仓库内容；域名是可变的外层标识，不应该固化进仓库名。

拆分触发条件（暂定，仅作判断依据，不是计划）：

1. 插件需要与站点不同的发版节奏；
2. 两边的 CI 开始互相拖慢；
3. 出现第二个消费同一索引的前端。

### 公开契约

- `https://dshbazaar.io/api/index.json` 会被用户写进 DSH 插件市场设置，视为公开契约，换路径或换域名都会让用户失效。
- 站点使用绝对路径（`/assets`、`/zh`、`/api`），**必须部署在域名根路径**，不能放到 `username.github.io/repo/` 这类子路径。

## 0002 · 抽样与页面集合解耦（2026-11-13）

| 对象 | 决定 | 说明 |
|---|---|---|
| 收录集合 | 显式配额：总榜前 N + 近 30 天新增前 M | 不再用多个按 star 排序的窗口取并集 |
| 页面集合 | 抽样 ∪ 曾经收录且仓库仍存在 | 掉出抽样不删页面 |
| `retained` | 只出详情页、搜索与 sitemap | 不进列表、标签页、首页、`index.json` |
| 页面下架条件 | 仓库 404 或 archived | 复核失败不算 |

**为什么**：2026-11-12 两封 Search Console 通知报的都是 `Not found (404)`。核对下来，robots / canonical / noindex / 分页都正常，站内没有悬空链接，sitemap 2,606 条 URL 全部 200。真正的原因是详情页集合每天在变——11/9 与 11/12 两次构建共 1,092 条里只有 579 条重合，抽 10 个被下架的仓库去查，10 个都还在 GitHub 上且仍带 `dsh-plugin` 话题。

**为什么不改成全量镜像**：话题下 3 万多个仓库，全量会让站点从 1 千页涨到 6 万页，构建时间和抓取预算都不划算；而且大量条目只有 0–3 star，没有收录价值。抽样保留，但页面不再跟着抽样抖动。

**为什么 retained 不进列表**：列表是「今天值得看的」，每天刷新是它的职责；页面是「别让旧链接断掉」，两件事不该互相牵制。

**已知代价**：仓库改大小写或改名时，旧 URL 仍会 404（GitHub Pages 不能 301，只能重新生成页面）。若要彻底解决，需要一层能写 redirect 的 CDN，或为改名仓库生成 meta-refresh 跳转页。
