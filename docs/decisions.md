# 决策记录

## 0001 · 命名与仓库划分（2026-11-09）

| 对象 | 决定 | 说明 |
|---|---|---|
| npm 包名 | `dsh-bazaar` | 安装标识，发布后不再改 |
| 站点品牌 | 「DSH 插件市场」 | 与包名解耦，可随时调整，不影响安装命令 |
| 域名 | `dshbazaar.io` | 站点部署在域名根路径 |
| 仓库 | `dshbazaar/dshbazaar` | 单一仓库，不按域名命名 |

**为什么仓库不叫 `dshbazaar.io`**：GitHub 仓库名与域名无关，`.io` 结尾反而让 URL 读起来像网址；自定义域生效后，Pages 服务在域名根路径，默认子路径那层不会暴露给用户，改名没有收益。

**为什么现在不拆仓**：站点、索引生成、插件三者共用同一份数据格式与构建脚本，拆开会先引入跨仓同步成本。按职责拆分留到确有需要时再做。

### 未来若拆分

- `dshbazaar/plugin` —— DSH 插件包（`packages/dsh-bazaar` 独立出去）
- `dshbazaar/site` —— 站点与索引生成

理由：按职责命名比按域名命名更能表达仓库内容；域名是可变的外层标识，不应该固化进仓库名。

拆分触发条件（暂定，仅作判断依据，不是计划）：

1. 插件需要与站点不同的发版节奏；
2. 两边的 CI 开始互相拖慢；
3. 出现第二个消费同一索引的前端。

### 公开契约

- `https://dshbazaar.io/api/index.json` 会被用户写进 DSH 插件市场设置，视为公开契约，换路径或换域名都会让用户失效。
- 站点使用绝对路径（`/assets`、`/zh`、`/api`），**必须部署在域名根路径**，不能放到 `username.github.io/repo/` 这类子路径。
